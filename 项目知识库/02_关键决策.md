# 关键决策

## 产品与视觉

- 以手机竖屏 1080×1920、30 fps 为默认输出，顶部和底部保留刘海屏安全区。
- 使用一个持续的 CanvasWorld 贯穿全片，章节通过镜头和动作转场连接。
- 采用 Apple 扁平化设计令牌；视频默认不使用静态卡片加大段文字。
- 进度条、中文字幕、口播、动画 beat 共用同一时间线。
- 进度条固定为五个等宽格 `开场 | 原理 | 案例 | 应用 | 结论`，每格文字水平垂直居中；钩子归入结论格，结论格直到 hook beat 结束才完成。
- GitHub 默认开场固定话术为“图解万物 之 GitHub 篇，今天要介绍的是 {projectName}，截止目前已斩获 {starCount} 颗星。”；星团由项目名称标签和确定性粒子构成，镜头沿 Z 轴平滑推进到目标项目。
- GitHub 周榜主源固定为 `https://github.com/trending?since=weekly`，榜单快照必须记录 URL 和抓取时间。

## 架构

- .NET WinForms 是编排器和用户入口；Node.js 是内容与 Remotion 运行时；Python 是 Kokoro 运行时。
- 每个节点声明输入、输出、版本、配置、缓存键、进度和检查点。
- 默认节点覆盖资料、事实、讲稿、钩子、故事板校验、配音、音乐、画布合成、渲染、字幕、质检和导出。
- 第三方节点包在 MVP 只预留契约，后续再加入签名、权限和安装流程。
- AI 生成和校验以 `specs/*.json` 为单一机器可读入口，规格校验失败必须阻断渲染。

## 成本与事实

- 外部模型服务可配置并缓存；本地 Kokoro 生成配音。
- 事实和案例必须保留来源、采集时间、证据标签和可信度；无法核实的内容只能标为假设。
- BGM 只允许本地授权或用户导入，语音播放期间自动 ducking。
- Kokoro 的全部配置音色在启动/版本变化预热阶段生成模型缓存和标准试听 WAV；音色页只读取 `VoiceCacheManifest`，试听不得触发首次加载。
- 画面 `displayText` 与口播 `pronunciationText` 分离；英文 token 依赖词典/phoneme hint，整数使用中文单位转换。
- 批量选择、队列、缓存、发音、音频时间线、进度、单例和导出路径等核心逻辑先写测试再实现；每轮变更必须同步知识库并提交。
- FFmpeg 由应用自动发现：优先显式 `MVP_FFMPEG_PATH`，其次当前新项目 Remotion 依赖内置运行时，最后系统 PATH；正常安装下不要求用户手工配置。
- 每轮代码完成后必须测试、执行 Release 构建并发布到固定 `artifacts/MotionVideoPipeline.exe`，验证发布物后同步项目知识库和协作永久记忆，再创建原子提交。
- 每轮协作完成后，在本地提交完成并通过验证后，必须将当前分支推送到配置的远程仓库和对应分支；推送失败必须记录具体原因，不得伪称已推送。远程 URL 不得包含 Token，凭据只能通过 Git 凭据管理器或临时安全凭据提供。

## 自动化与领域包

- 默认批量任务使用 GitHub 最近一周推荐/Trending 榜单，`batchCount` 可配置为 1–100，默认 10；候选不足或单项目失败不得用虚假项目补足，按策略继续或隔离。
- AI 自动负责选题、资料规划、资料采集、去重、事实核验、讲稿、钩子、配音、BGM 选择、动画编排、渲染、质检和导出。
- `github-open-source` 必须随产品交付并可直接运行，不需要用户人工制作领域包。新领域通过自然语言输入由 AI 生成 `domain.json`、采集器、提示词、钩子、视觉主题和质量规则。
- 人工介入只保留为高风险领域合规审核、外部授权、来源白名单和品牌治理；不得成为普通 GitHub 批量任务的逐项目门禁。
