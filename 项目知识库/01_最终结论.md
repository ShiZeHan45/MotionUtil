# 最终结论

1. 产品采用 WinForms 单例桌面入口，核心是可观察、可恢复、可替换且默认自主运行的内容生产流水线。
2. 固定视频骨架为五个主章节：开场、原理、案例、应用、结论；钩子是结论章节最后的 `kind="hook"` beat，不是第六个章节或进度格，单条视频最多 5 分钟。
3. Remotion 负责帧编排与导出，Three.js 负责连续无边画布中的空间图形、背景运动和镜头，Kokoro 负责本地中文配音。
4. 资料只用于事实核验和证据引用，视频需要 AI 结构化重述和程序动画，不直接把静态资料页面当成成片。
5. 模型、领域包、资料源、音色、BGM、视觉主题和部分节点均配置化；节点通过 JSON schema 和版本化契约连接。
6. 成品、字幕、故事板、证据包和质量报告可以按项目保存；EXE 统一输出到固定 `artifacts/` 目录。
7. 用户指定的远程目标为 MotionUtil 的 `f_rebuild` 分支，但工程初始化必须从新项目边界开始，不能复制旧业务实现。
8. AI 执行必须以 `specs/` 下的视觉令牌、银河开场、进度条、故事板、CanvasWorld 和质量门禁规格为输入，先校验再生成代码或媒体。
9. 默认主流程是“GitHub 周榜 → AI 自动选 N 个项目 → AI 自动采集和核验资料 → 自动写稿/钩子 → Kokoro 配音 → Remotion + Three.js 渲染 → 自动质检导出”；普通 GitHub 批量生产不要求人工逐项目介入。
10. `github-open-source` 领域包由产品内置；其他低风险领域包可由 AI 根据自然语言描述生成和验证，高风险领域仅在合规治理边界需要人工审核。
11. GitHub 周榜主源固定为 `https://github.com/trending?since=weekly`，快照必须记录实际源 URL；全量音色在音色页交互前完成本地预缓存，试听不得懒加载。
12. 英文专名必须通过发音词典或 phoneme hint，阿拉伯整数必须转换为中文单位读法，例如 `12345` 读作“一万两千三百四十五”；核心逻辑采用 TDD，视觉和 AI 模型节点采用 schema/快照/回放验证。
13. 每轮改动都必须更新知识库，并创建包含变更、验证和风险/待办说明的原子提交。
