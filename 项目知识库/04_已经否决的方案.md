# 已经否决的方案

- 直接复用旧项目的业务代码、旧 `node_modules`、旧发布目录或旧输出结构。
- 用静态“卡片 + 文字”拼接整条视频，开场直接展示一张静态图。
- 把 README、网页截图或项目资料原样当作讲稿和案例结论。
- 把模型、Kokoro 音色、资料源和领域规则硬编码进单个流程函数。
- 默认接入短视频平台自动发布。
- 默认使用文生图或图生视频替代可控的程序动画。
- 把片尾钩子做成独立的第六个章节或进度格，导致顶部进度条不再是 `开场 | 原理 | 案例 | 应用 | 结论` 五格。
- 每次构建都创建一个新的带日期或版本号的 EXE 目录。
- 把“人工准备领域包、人工粘贴资料、人工逐项目选题”作为 GitHub 周榜批量任务的启动前置条件。
- 用户点击试听时才懒加载 Kokoro 模型或首次生成试听音频；音色必须在应用可交互前完成全量预热和缓存。
- 把核心编排、队列、缓存、数字转换或音频时间线逻辑先实现、事后补测试；这些模块必须先以失败测试定义行为，再实现和重构。
- 将 `12345` 等阿拉伯整数逐位朗读为“一二三四五”，或让未经词典/phoneme hint 覆盖的英文专名静默猜读。
