# 协作永久记忆

本文件记录后续协作必须持续遵守的项目约定。跨任务继续开发时先读取本文件及 `00_项目总览.md`、`02_关键决策.md`、`03_需求与约束.md`、`05_当前进度.md`、`06_待解决问题.md`、`07_历史对话.md`。

## 每轮交付流程

1. 代码变更完成后运行适用的测试和规格检查。
2. 执行 Release 构建并发布 EXE；固定路径为 `artifacts/MotionVideoPipeline.exe`，不得创建版本目录或日期目录。
3. 运行发布物检查，记录 EXE 路径、构建结果和验证结果。
4. 更新 `05_当前进度.md`、`06_待解决问题.md`、`07_历史对话.md`，并在本文件维护持续有效的协作约束。
5. 创建原子提交，提交正文包含“变更”“验证”“风险/待办”三项；不自动推送。

## 环境与实现约定

- FFmpeg 不要求用户手工安装或配置 PATH。自动发现优先级：`MVP_FFMPEG_PATH`、当前新项目 Remotion 包内置 FFmpeg、系统 PATH。不得复制旧项目中的媒体运行时。
- 模型缺失时真实任务阻断；只有显式测试/开发参数可以启用固定 JSON 夹具。
- 核心业务逻辑尽量采用 TDD；视觉和大模型调用使用 schema、快照、固定夹具和渲染验证。
- 不提交 API Key、GitHub Token、个人密钥、旧项目业务代码、依赖目录、虚拟环境或大型临时文件。
- 每次协作都更新项目知识库；如当前会话没有可写入的独立全局记忆接口，以仓库中的本文件作为版本化、可持续检索的协作记忆。
